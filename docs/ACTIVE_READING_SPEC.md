# Active-Reading Layer — feature spec (draft for owner decision)

**Status:** proposal / not built. **Author:** web session 2026-07-24. **Origin:** the "active reading
protocol" idea (spaced-repetition / active-recall / apply-within-48h) surfaced in the 2026-07-24
learning-science assessment, cross-checked against what the site already has.

## 1. Problem
The deep-dive essays (`library/*.html`, ~1,800–2,600 words each) are the heart of the site — but they
are read **passively**. The site already turns *arguments* into active recall (flashcards + SM-2, the
`/today` loop, and **Explain It Back** on the 67 mastery pages), but the **essays themselves have no
active-recall scaffolding**. A reader can finish a 2,400-word essay having *recognized* everything and
*retained* little. This is the one genuine gap the learning-science review found (the tweet's "teach-back"
and "spaced repetition" prompts are already covered by Explain It Back + SM-2; "active reading" is not).

## 2. Goal
Convert passive essay reading into active recall **without breaking the reading flow or the scholarly
tone** — and feed what the reader gets wrong back into the existing retention machinery (flashcards /
Coach), so a weak essay section becomes a scheduled review.

Non-goals: not a new AI chat surface (the tutor already exists), not gamification for its own sake, not
anything that adds hype. Confidence earned by engagement, not badges.

## 3. What it is
A lightweight **"Section Checkpoint"** injected at the essay's natural section breaks (`<h2>`), plus a
**closing "Take it with you"** step. Two checkpoint variants (start with variant A):

- **A. Recall prompt (MVP, zero AI cost):** after a major section, a collapsed one-line prompt —
  *"Before you scroll on: in a sentence, what's the load-bearing claim of this section?"* — with a
  **"show the answer"** reveal that displays the section's own key sentence (curated once per essay).
  Pure active recall (the testing effect), no API call, works offline/preview.
- **B. Explain-a-section (AI-scored, reuses `/api/tutor`):** a free-text box — *"Put this section in your
  own words"* — scored by the **existing `/api/tutor` endpoint**, which *already accepts an `excerpt`
  and grounds its feedback on the certified essay text* (see `api/tutor.js` line 61–68). Same mechanism
  as Explain It Back, but scoped to one section instead of the whole argument.

**Closing step — "Take it with you" (the tweet's "apply within 48 hours"):** at the essay end, one
prompt: *"Where could this come up this week?"* + a **"save as a flashcard"** button that seeds the
existing SM-2 deck with the essay's core claim. This is the retention hook.

## 4. Where it plugs in
- **Template:** `library/manuscript.html` (the essay template) gains an optional checkpoint partial;
  essays opt in by marking section breaks. A build helper can auto-insert variant-A checkpoints after
  each `<h2>` from a per-essay data block.
- **Reuses, does not rebuild:**
  - `api/tutor.js` for variant B (already grounds on `excerpt`; already guardrailed — and, per the
    2026-07-24 gate, now stamped).
  - The flashcard + SM-2 store for "save as a flashcard" (same store the `/today` miss-seeding uses).
  - `Coach` — a low section score / missed recall marks that argument weaker in the skill map (same
    path as the `/today` self-rate → `Coach.recordQuiz`).
  - `localStorage` progress key per essay (mirror `ad_mastery`), e.g. `ad_read_<slug>` = sections
    checkpointed — drives a subtle per-essay "actively read" state, not a score to chase.
- **Discovery:** show an "actively read" check on the library index card once all a page's checkpoints
  are done; optionally surface an essay's checkpoints as a `/today` drift step.

## 5. Content-pipeline implications (important)
The checkpoint text is **content** and must respect the gates:
- **Variant A curated answers** = the section's own already-certified sentence, pulled verbatim from the
  essay → inherits the essay's certification; **no new gate needed** IF it's a true excerpt (a build
  check can assert the "answer" string appears verbatim in the essay body, like the answers-drift audit).
  If a checkpoint *rewrites* the claim, that rewrite needs argument + orthodoxy stamps.
- **Variant B feedback** = generated by `/api/tutor`, which is now gated/stamped → inherits that
  certification. Any change to the tutor's grading instruction re-clears argument + orthodoxy.
- **No hand-written doctrinal Q&A** ships unstamped. Prefer "answer = verbatim essay sentence" so the
  layer stays certification-free by construction.

## 6. Phasing
- **Phase 1 (MVP):** variant A (recall + reveal) on **~5 pilot essays** (pick high-traffic, self-contained
  ones — e.g. `kalam`, `minimalfacts`, `emptytomb`, `manuscript`, `moral`). Build helper + the
  verbatim-answer build check + `localStorage` progress. No API cost. Measure completion.
- **Phase 2:** the closing "Take it with you" + flashcard seeding + the library-index "actively read"
  check + Coach hook.
- **Phase 3:** variant B (explain-a-section via `/api/tutor`) on the pilot set; then roll A across all
  essays and B where it earns its API cost.

## 7. Metrics
- % of essay readers who complete ≥1 checkpoint (activation).
- Flashcards seeded from "Take it with you" (retention intent).
- For variant B: mean section score, and whether Coach mastery for that argument improves on re-quiz.
- Guardrail metric: essay scroll-depth / completion should NOT drop (checkpoints must not feel like a
  wall) — kill or soften if it does.

## 8. Guardrails / risks
- **Reading flow first.** Checkpoints are **collapsed by default** and skippable; never a modal, never a
  gate that blocks scrolling. A reader who ignores them loses nothing.
- **Tone.** Prompt copy stays plain and non-gamified ("Before you scroll on…"), never "learn faster than
  99%." No streak-shaming.
- **Cost.** Variant A is free (no API). Variant B is rate-limited via the existing `overRateLimit`
  ('tutor', 80/day) — watch spend before wide rollout.
- **Certification-by-construction** (see §5): default to verbatim-from-essay answers so the layer can't
  drift doctrinally.
- **Accessibility:** keyboard-reachable, screen-reader labels, respects reduced-motion.

## 9. Decisions needed from the owner
1. **Start at variant A only?** (Recommended — free, fast, proves the retention lift before spending
   API budget on B.)
2. **Pilot essay set** — confirm the ~5.
3. **Should checkpoints count toward mastery** (like Explain It Back / flashcards do), or stay a
   pressure-free reading aid? (Recommend: pressure-free in Phase 1; revisit after the completion metric.)
4. **Gate posture for curated answers** — accept the "verbatim-from-essay + build check" shortcut
   (recommended), or require an explicit stamp per essay?

---
*This is a spec, not an implementation. Nothing here is built or deployed. Build would follow the normal
flow: apologia-product/-growth sanity check → build → (for any new doctrinal text) argument + orthodoxy
gates → deploy.*
